# Token efficiency research for project loops and Agent Studio

Researched 2026-09-08. Primary documentation and original repositories were opened and checked. This document recommends implementation patterns; it does not claim measured savings in this workspace.

The best first changes are to prevent repeated information from entering context, keep the current mission and constraints in durable state, and retrieve detailed evidence only when needed. Keep the current model and reasoning capability while removing waste. Provider prompt caching lowers the cost of processing eligible repeated prefixes; it does not make a growing conversation smaller.

## Implementation priorities

1. **Stop transcript echo.** Deliver events after a persistent receiver cursor. Give each event an ID and origin. Acknowledge delivery separately from processing. Never re-forward received envelopes as new messages. Coalesce unchanged status before invoking a model; changed status, blockers, and completion still pass through.
2. **Keep a durable mission.** Store the user objective, subsequent corrections, constraints, decisions, outstanding work, and evidence references outside the rolling transcript. Include a compact current mission in each fresh agent context. Update existing facts explicitly instead of appending contradictory summaries.
3. **Use bounded handoff envelopes.** Carry assignment, outcome/change, evidence references, unresolved questions, and requested next action. Store large source output first and attach a stable reference. If a message cannot be safely reduced, retain the original and signal that more context is available. Do not silently cut arbitrary characters from critical instructions.
4. **Budget assembled context.** Account separately for instructions, mission, recent turns, retrieved memory, tool output, and inter-agent messages; reserve response headroom. Keep complete current user requests and tool interactions. Compact completed work first. Expose estimated versus provider-reported tokens honestly.
5. **Avoid unnecessary invocations.** Poll state without a model where possible. Use revision IDs and exponential backoff for unchanged state. Detect repeated no-progress rounds and persist a recoverable checkpoint; do not silently stop required work just to satisfy a token cap.
6. **Make evidence concise at its source.** Search targeted ranges and return relevant fields; summarize successful repetitive logs and keep full failures retrievable. Exact read-only caches must include request arguments and relevant state/version/tenant identity, with invalidation. Never cache execution of mutations as if it were a read.
7. **Apply model-compatible caching and compaction.** Keep prefixes stable; move timestamps and changing status later. Measure cache read/write tokens and total input cost. Compaction may reduce cache hits while still lowering total input cost. These API capabilities do not establish configurable behavior or subscription savings in the ChatGPT interface.

## Preserve quality and verify savings

Use fixtures representing large peer messages, duplicate retries, fresh identical messages with different event IDs, long tool results, mission corrections, compaction, and restart/resume. Verify that constraints and unfinished work survive, complete tool-call/result groups remain valid, references recover original content, distinct events are not lost, and completed/error notifications still arrive. Test two agents with repeated unchanged state to confirm bounded message growth and fewer invocations.

Report before/after assembled tokens and message bytes, suppressed duplicate deliveries, model-call counts, cache reads/writes, latency, and task outcomes on the same workloads. Structural tests establish protocol correctness; they cannot prove unchanged reasoning quality. Benchmark lossy compression, semantic caching, and cheaper model routing separately before turning them on. No percentage savings should be claimed from vendor benchmarks or character counts alone.
